# UPTET Saathi

Offline-first, bilingual (Hindi/English) revision app for UPTET, Super TET and CTET candidates. Flutter + sqflite,
Android only.
Goal for the pilot: run free apart from the Google Play developer account, so no backend or paid services.

## Commands

```
flutter test                                  # all tests (sqflite_common_ffi, no device needed)
flutter analyze
dart run tool/validate_content.dart           # validate assets/content/content_pack.json
flutter build apk --release                   # build/app/outputs/flutter-apk/app-release.apk
flutter build appbundle                       # build/app/outputs/bundle/release/app-release.aab (for Play)
```

Run all three checks after any change to the content pack or the content model.

Python import scripts run from the repo's `.venv`, created with the Windows Python
(`C:/Users/meher/AppData/Local/Programs/Python/Python313/python.exe -m venv .venv`; the `python` on
Git Bash's PATH is MSYS and makes a broken venv). Run them as `.venv/Scripts/python -I tool/pyq/<script>`.

## Layout

- `lib/models/content.dart`: content pack model (subjects, topics, questions, papers) and JSON parsing.
- `lib/models/content_index.dart`: lookups over the installed pack (`papersFor(exam, level)`, paper languages).
- `lib/app_state.dart`: `AppController` holds the language and the chosen exam (saved under the `exam`
  settings key). The exam switch (`ExamSwitch` in `lib/widgets/brand.dart`) appears only on the pages whose
  content depends on the exam: Papers (lists that exam's papers) and Syllabus (shows its pattern). Keep it
  out of the shared header; practice, subjects, revision and progress cover all exams.
- `lib/database/app_database.dart`: schema as a list of append-only migrations. Never edit a shipped
  migration; add a new entry. `test/database/app_database_test.dart` upgrades v1 to current.
- `lib/repositories/`: SQLite access. `content_repository.dart` installs the bundled pack.
- `lib/services/content_validator.dart`: pack checks. Release rules are errors only when
  `release_ready` is true, otherwise warnings.
- `lib/services/scoring.dart`, `revision_scheduler.dart`, `progress_calculator.dart`: tunables live in `lib/config.dart`.
- `lib/l10n/strings.dart`: all UI strings, in both languages.
- `tool/pyq/`: Python scripts that import previous papers from PDFs (see its README).

## Content rules

- `assets/content/content_pack.json` is generated by `tool/pyq/build_uptet.py`, `build_supertet.py` and
  `build_ctet_feb26_p1s.py`. Fix UPTET content in the section modules (`tool/pyq/u17|u18|u19|u21`) and
  Super TET content in `tool/pyq/st19`, and rebuild, not by hand in the JSON, or the next rebuild loses
  the fix. Each builder replaces only its own papers and questions (`uptet-*`, `supertet-*`).
- Bump `content_version` whenever the pack changes; the app reinstalls the pack only when it differs.
- Official papers need `exam` (uptet/supertet/ctet) and `level` (primary/junior; Super TET is primary).
  A paper lists its own `question_ids`, so Junior papers share their common parts. A new exam needs a
  value in `Exam` (`lib/models/content.dart`), its name in `strings.dart` and a pattern on the Syllabus page.
- Subjects with `language` (hin, eng, and san, which is asked in Hindi) hold questions in that language only.
- A paper's booklet is bundled as `assets/pdfs/<paper id>.pdf`; the app finds it by that name even when
  `pdf_asset` is null. For Super TET 2019 this is the clean retypeset Series A booklet (the scan in Drive has
  a candidate's pen marks). The UPTET PDFs are cut from the YCT solved papers in Drive (folders 17, 18, 19,
  21) to the question pages and the answer key page: never bundle YCT's explanation pages, which are the
  publisher's own text (see `tool/pyq/README.md`).
- Explanations are our own writing. Answers follow the source key; skip questions whose answer is
  wrong or ambiguous or that need a figure, and note disputed answers in the explanation.
- Every imported question stays `verification_status: pending_review` until checked against the
  official booklet and final key.

## Before going live

- `distribution_cleared` and `release_ready` stay false until written permission arrives from
  the rights holders: CBSE for CTET, and Pariksha Niyamak Pradhikari UP, Prayagraj
  (updeled.gov.in) for UPTET and Super TET. examregulatoryauthorityup.in is not an official site.
- Release builds are signed with the Play upload key named in `android/key.properties` (git-ignored; the
  keystore lives outside the repo). Without that file they fall back to the debug key. Check the signer with
  Android Studio's keytool (`C:/Program Files/Android/Android Studio/jbr/bin/keytool.exe -printcert -jarfile
  <aab>`); the JDK 23 on PATH has no keytool.
- `store/` holds the Play material: `listing.md` (English and Hindi text), `play-console.md` (App content
  answers, release checklist), `privacy-policy.html` (to host publicly), icon and feature graphic. Keep the
  listing in step with the app's features, and keep the "not affiliated" disclaimer in both the listing and
  the About screen (Play policy for apps with government information).
- Raise the build number in `pubspec.yaml` for every upload to Play.
